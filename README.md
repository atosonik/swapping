# Face Swap

Offline desktop face swapper. Open a photo, click the face you want replaced,
pick the new person's photo, swap. No PyTorch, no cloud, no telemetry — the
whole pipeline is onnxruntime, and it runs with the network unplugged.

![steps](https://img.shields.io/badge/pipeline-detect%20%E2%86%92%20embed%20%E2%86%92%20swap%20%E2%86%92%20tone--match-4c8dff)

## First run after cloning

The model files are **not** stored in this repo as-is — they are committed as
≤1 MB parts under `parts/`, so the first step is to reassemble them:

```
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python chunker.py merge        # parts/ -> models/  (750 MB, ~1.2 s, checksummed)
python selftest.py             # 18 checks, should end "All checks passed."
python ui.py                   # the app
```

If `parts/` is missing or you would rather fetch the models fresh, use
`python download_models.py` instead — it does the same job over the network.

## What it uses

| Stage | Model | Size |
|---|---|---|
| Face detection + 5 keypoints | SCRFD `det_10g.onnx` | 17 MB |
| Face contour (106 pts) | `2d106det.onnx` | 5 MB |
| Identity embedding | ArcFace `w600k_r50.onnx` | 174 MB |
| Identity transfer | `inswapper_128.onnx` | 554 MB |

The first three ship together as InsightFace's `buffalo_l` pack.

## Install

Verified on Windows 11 + Python 3.12, CPU only. `insightface==0.7.3` builds from
source but needed **no** Visual Studio Build Tools here — pip resolved it without
a compiler. If it does fail on your machine, install the "Desktop development
with C++" workload and retry.

## Run

```
python selftest.py                                   # verify the install
python ui.py                                         # desktop app (Help button, or F1)

python cli.py photo.jpg --list -o boxes.jpg          # numbered preview of every face
python cli.py photo.jpg new.jpg --face 2 -o out.jpg
python cli.py photo.jpg new.jpg --point 812 430 -o out.jpg
python cli.py photo.jpg new.jpg --face 1 --tone 0.8 --blend 0.9 -o out.jpg
```

The output path is the `-o` flag, not a positional argument. `--face` is
1-based, matching the numbers drawn on the `--list` preview and shown in the GUI.

## The standalone .exe

A single-file Windows build lives in this repo as parts, same as the models:

```
python chunker.py merge --parts runableparts     # -> dist/FaceSwap.exe (180 MB)
```

It needs no Python. It does need `models/` **next to the .exe**, so a working
folder looks like:

```
FaceSwap.exe
models/            <- from: python chunker.py merge
```

`FaceSwap.exe --selftest` runs the same 18 checks as `selftest.py` without a
Python install — the packaged build passes all of them, cold start included, in
about 13 s. Add a `testdata/` folder beside the exe for the image checks.

To rebuild it:

```
pip install pyinstaller
python -m PyInstaller --noconfirm --clean FaceSwap.spec
```

[FaceSwap.spec](FaceSwap.spec) is not a stock PyInstaller spec — read the two
comment blocks in it before changing anything. In short: `onnxruntime` must not
be `--collect-all`ed (its analysis subprocess crashes on `onnx.reference`),
`matplotlib` cannot be excluded however unused it looks (`insightface.app`
imports it transitively at import time), and the bundled MSVC runtime DLLs are
stripped because PyQt5 and scikit-learn ship different builds under the same
filename and the loser breaks onnxruntime.

The exe is console-mode on purpose: a onefile GUI that dies during import has no
window to show an error in, and silence is worse than a console flash. It also
extracts ~180 MB to a temp folder on each launch, which is what onefile costs.

## Models and the network

`python download_models.py` stages everything into `models/`, reusing an existing
`~/.insightface` cache if you have one. After that the app never touches the
network — `swapper.py` sets `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` and
`NO_ALBUMENTATIONS_UPDATE` before any model library is imported. That last one
matters: `albumentations` otherwise makes a blocking HTTPS version check on
import, which stalls startup for seconds on an air-gapped box.

Offline behaviour is tested, not assumed — the pipeline has been run end to end
with `socket.socket.connect` patched to raise on any call.

**Where `inswapper_128.onnx` comes from:** InsightFace withdrew the official
release in 2023, so `download_models.py` falls back through four community
mirrors. Expected size is **554,253,681 bytes**, sha256 `e4a3f08c…16af`.

The mirrors are *not* guaranteed byte-identical, so a partial download is only
ever resumed against the mirror it started from. Resuming across mirrors splices
two byte streams into a file of roughly the right size that then fails with
`INVALID_PROTOBUF` at load — this happened during development. The downloader
deletes the partial file before switching mirrors and parses the finished model
with `onnx.load()` rather than trusting its size.

## Tuning for East Asian faces

`inswapper_128`'s 128px decoder drifts warm and light. On Asian skin tones that
reads as a wrong complexion and leaves a visible seam at the jaw. Its training
distribution is not published, so treat any explanation of *why* as speculation —
what is measurable is the drift, and the correction.

The pipeline applies a LAB mean/std colour transfer inside the face contour,
matching the swapped face back to the original face's own lighting. **Skin tone
match** in the UI controls it; 70–100% is the useful range. It corrects colour
only: identity lives in high-frequency detail that first-order statistics leave
alone.

`python selftest.py` reproduces these on the bundled test images:

| Check | Result |
|---|---|
| Self-swap, cosine to the original identity | **0.811** (1.0 = identical) |
| Cross-swap, cosine to the *source* person | **0.634** (ArcFace calls >0.4 same person) |
| Cross-swap, cosine to the *original* face | **0.168** (identity genuinely replaced) |
| Skin-tone ΔE vs the original face, tone 0 → 1 | **2.18 → 0.89** |

Self-swap falls short of 1.0 because of the 128×128 bottleneck, not a defect.

Two things matter more than any slider:

- **Match the pose.** The single biggest quality lever. Swapping a frontal source
  onto a face pitched steeply downward produced a visibly smeared result here even
  though the identity metric still read 0.634 — the model transferred the right
  face and then rendered it badly. Pick a source photo shot from roughly the same
  angle as the target.
- **Don't swap the recogniser.** `inswapper_128` carries a baked-in `emap` matrix
  fitted to `buffalo_l`'s `w600k_r50` embedding space. Substituting `antelopev2` —
  often suggested because it scores better on Asian benchmarks — feeds it
  embeddings from a different space and degrades the output to a blurry average
  face. `buffalo_l` is not optional here.

## Splitting big files into parts

[chunker.py](chunker.py) cuts a file or folder into parts of at most 1 MB and
puts them back byte-for-byte, for when the whole file can't be moved in one
piece — a size-limited transfer, or a git host.

```
python chunker.py split                                  # models/ -> parts/
python chunker.py split --src dist/FaceSwap.exe --parts runableparts
python chunker.py verify --parts runableparts               # checksum only, writes nothing
python chunker.py merge  --parts runableparts               # restores dist/FaceSwap.exe
```

Default part size is **1,000,000 bytes** — under "1 MB" whether read as 10⁶ or
2²⁰. `--size` accepts `900KB`, `1MiB`, `512K`.

The manifest records a SHA-256 for every part *and* for each whole file. `merge`
checks both and assembles into a `.merging` temp file that is only moved into
place once the full-file hash matches, so a bad part can never leave a
half-written file where something would load it. Verified against all three
failure modes:

| Damage | Result |
|---|---|
| One bit flipped, size unchanged | `part 00250.bin failed its checksum`, exit 1 |
| Part truncated | `is 900000 bytes, expected 1000000`, exit 1 |
| Part deleted | `1 part(s) missing, first 00250.bin`, exit 1 |

A size check alone would miss the first of those. Splitting a single file puts
its parts flat in the output folder; splitting a directory mirrors the tree.
`merge` skips anything already correct, so re-running it is cheap. For `models/`
only the four files the app loads are split — `--all` adds `1k3d68.onnx` and
`genderage.onnx`, ~145 MB the app never touches.

## Import order (do not "tidy" this)

`ui.py` imports `swapper` **above** its PyQt5 imports, and `swapper.py` imports
`onnxruntime` eagerly at module scope. This is load-bearing on Windows:

```
import onnxruntime; from PyQt5 import QtWidgets   # works
from PyQt5 import QtWidgets; import onnxruntime   # DLL initialization routine failed
```

Letting an import sorter alphabetise those lines makes the GUI crash on startup
with a bare `0xC0000409`, which points nowhere near the real cause. `swapper.py`
catches that ImportError and re-raises it with an explanation.

## Known limits

- Output face is **128×128** before paste-back. On a phone-resolution photo it
  will look softer than the rest of the frame. A GFPGAN/CodeFormer restoration
  pass is the usual fix; it is not wired in. If you add one, prefer CodeFormer at
  a high fidelity weight (~0.7–0.9) — its face prior otherwise pulls features
  toward its own training distribution.
- No CUDA provider was available in the environment this was built and measured
  in, so all timings are CPU: ~1–2 s per swap. Swap `onnxruntime` for
  `onnxruntime-gpu` (CUDA 12 + cuDNN 9) for roughly 40 ms.
- Glasses, heavy occlusion and extreme profiles all degrade the result.
- Slider recomposites are limited to the region the swap actually touched
  (measured 1435 ms → 427 ms on a 22 MP photo) and debounced by 120 ms, so
  dragging stays responsive. They still scale with image size, because the face
  scales with it.
- One face at a time. Replacing a second face means saving and reopening the
  result; the app does not yet chain swaps.
- The GUI has been verified by offscreen render and scripted tests rather than
  by a human clicking through every path.
